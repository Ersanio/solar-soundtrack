AddmusicK 1.0.11 command truth table

Every MML text command, # directive, hex command and subcommand that AddmusicK 1.0.11 recognises: what the SPC700 driver does with it, what the compiler does with it, and under which target directive (#amk 1, #amk 2, #amk 4, #am4, #amm) it is accepted as written, rewritten, warned about, refused, or accepted and then dead on the driver.

This is a developer reference for Solar Soundtrack, written against the local reference copy of AddmusicK 1.0.11 in AddmusicKsrc/ and AddmusicKreadme/. It is not a porter's manual; the readme is. Where the two disagree, this document says so and cites the line that settles it. Sound-effect MML (SoundEffect.cpp, sound_effects.html) is a different language with no version directive and is out of scope; note only that an SFX stream reuses several of the same byte values with different meanings (main.asm:918-1002).

0. How to read this

Citations

Music.cpp:1789, globals.cpp:947, Commands.asm:633, main.asm:2368 are line numbers in AddmusicKsrc/; hex_command_reference.html:224 and syntax_reference.html:105 are lines in AddmusicKreadme/readme_files/. main.bin @ $136C is an ARAM address in the assembled driver AddmusicKsrc/bins/main.bin, whose byte 0 loads at ARAM $0400 (file offset = address − $400).

Two tables the driver dispatches on — CommandDispatchTable and CommandLengthTable — live in asm/CommandTable.asm, which is incsrc'd at main.asm:2780 and is not in AddmusicKsrc/ (nor are UserDefines.asm and InstrumentData.asm). They were recovered from main.bin by reading the dispatcher's own operands at ARAM $0D5A (main.asm:2656-2667, mov a, !$12B9+y / mov a, !$12B8+y / mov a, !$12DC+x): the dispatch table is at $12B8 + $B4 = $136C and the length table at $12DC + $DA = $13B6. Every entry was checked against the first bytes of the routine it points at.

The five target columns

The compiler's behaviour is steered by two static integers in Music.cpp: songTargetProgram (0 = AddmusicK, 1 = Addmusic 4.05, 2 = AddmusicM; Music.cpp:52) and targetAMKVersion (the #amk number, or 0 for #am4/#amm; Music.cpp:53). Only five combinations are reachable — see §1 — so every per-version table has these five columns, in this order:

Column songTargetProgram targetAMKVersion What it means
#amk 1 0 1 AddmusicK Beta's parser. Also written #amk=1.
#amk 2 0 2 AddmusicK 1.0 – 1.0.8.
#amk 4 0 4 AddmusicK 1.0.9 – 1.0.11, the current parser. Every >= 3 test in the source is in practice this column, because #amk 3 is refused.
#am4 1 0 A song written for Addmusic 4.05 (HuFlungDu).

Cell legend

native Accepted and emitted as written.
→ bytes Accepted and rewritten into different bytes; the cell says which.
warn Accepted and emitted, with a warning. Almost all of these are one-shot: a static flag silences the second and later occurrences in the same song (nonNativeHexWarning and friends, Music.cpp:91-101).
error Refused. error() counts towards errorCount and compilation aborts at pointersFirstPass (Music.cpp:2984); fatalError() aborts on the spot.

— Cannot occur under that target, or the question does not apply.

“Driver length” columns give the value in CommandLengthTable; “compiler length” gives hexLengths[] (Music.cpp:63-65). Both count the command byte itself. The driver's dispatcher uses the length for one thing only — whether to pre-fetch the first argument (dec a / beq, main.asm:2666-2667) — and the read-ahead uses the full value to step over commands (main.asm:3034), which is where a wrong length bites.

1.2 Rules that follow from the fields

  • #am4 and #amm win over #amk in either order. They assign version unconditionally; #amk N and #amk=1 assign only if (version >= 0), i.e. only while no #am4/#amm has been seen (globals.cpp:780, 927). The readme says the same (syntax_reference.html:410). Two #amk lines: the last one wins.
  • A third way into #am4, mid-song. An Addmusic 4.05 header write $ED $80 $6D xx or $ED $80 $7D xx sets songTargetProgram = 1 when it is parsed (Music.cpp:1510-1527) — but only if the song was already being parsed as #am4, since $ED is only routed to parseHFDHex under songTargetProgram == 1 (Music.cpp:1724). In 1.0.11 the assignment is therefore redundant.
  • Velocity table. usingSMWVTable = (targetAMKVersion < 2) (Music.cpp:377-381): #amk 1, #am4 and #amm start on SMW's quiet table; #amk 2 and #amk 4 start on N-SPC's, and get $FA $06 $01 in the prologue to say so (§1.3). The flag itself is read only by #option smwvtable (Music.cpp:2346).
  • Tuning is ignored until the first @ under #am4. ignoreTuning[0..8] = (songTargetProgram == 1) (Music.cpp:410-416); @N clears the channel's flag (:895-898) and [ copies it into the loop slot (:1240). Until then transposeMap[@] is not subtracted from note pitches (:2157-2158).
  • ; comments are stripped by the preprocessor for every target except #amm (globals.cpp:982-995), over the whole buffer and without regard for quotes — so "x=a;b" loses its tail. Only #amm songs ever deliver a ; to the parser, where parseComment skips to end of line (Music.cpp:494-513); the “Illegal use of comments” error there is unreachable.
  • Case. Three different rules. The preprocessor compares directive names with ==, so #amk, #amm, #am4, #define, #undef, #ifdef, #ifndef, #if, #endif are case-sensitive (globals.cpp:788-956). parseSpecialDirective uses strnicmp, so #instruments, #samples, #pad, #spc, #louder, #tempoimmunity, #path, #halvetempo, #option and the #option keywords are case-insensitive (Music.cpp:2415-2508, 2343-2396) — but the keys inside #spc { } are compared with != and are case-sensitive again (Music.cpp:3471). MML letters go through tolower (Music.cpp:445), so every text command is case-insensitive; upper-case notes draw a warning below #amk 4 (:2125-2128). The readme's “all ‘special’ commands are case insensitive” (syntax_reference.html:444) is therefore wrong for a third of them.
  • Starting channel. init() searches the whole text for the substrings "#0" … "#7" in that order and starts writing to the first one found (Music.cpp:385-400); it is a raw find, so a #1 inside a sample-group name would count. Notes before any #N are an error for AddmusicK targets and accepted for #am4/#amm (:2141-2142).

1.4 Tempo ratio

#halvetempo doubles tempoRatio, #option dividetempo N sets it (Music.cpp:2493-2503, 2379-2395). Durations are then divided and rates multiplied — but divideByTempoRatio returns its input unchanged for targetAMKVersion < 4 (Music.cpp:3664) while multiplyByTempoRatio has no version test (:3687-3694). So under #amk 1, #amk 2, #am4 and #amm a #halvetempo song has its vibrato and tremolo rates doubled and nothing else changed. The readme's #amk 4 note records the fix (syntax_reference.html:440). The full list of what is rescaled is in §4.3.

1.5 Command-line switches that change the rules

  • -h clears validateHex (AddmusicK.cpp:110; default true, globals.cpp:37). The whole body of parseHexCommand is inside if (validateHex) (Music.cpp:1681): no length tracking, no version conversions, no range checks — every $xx is appended raw — and the prologue of §1.3 is not inserted (Music.cpp:402). Everything in §4 assumes it is on.
  • -c clears convert (AddmusicK.cpp:98; default true, globals.cpp:30). It gates the #am4 $ED $80–$83 escapes (Music.cpp:1479-1556) and the @@19–@@29 → custom-instrument remap (:880-884).

2.1 Note lengths, ties and what is actually emitted

getNoteLength (Music.cpp:2906-2937): a number N in 1–192 gives 192/N ticks (warning once if it does not divide); anything else, including no number, gives the l default; =N gives N ticks directly, and below #amk 4 returns before dots and triplets are applied (:2918-2921). Dots add half, then a quarter, … (:2943-2961; #am4 stops after two dots, :2960); a triplet multiplies by 2/3 (:2968). Then divideByTempoRatio(j, true) (:2248) — an error, not a warning, if that leaves a fraction.

Following ^s (and rs after a rest) are merged into one length (:2213-2235), except that the merge rewinds and stops before a tie that precedes a $DD — or an & under #am4/#amm — so the bend has a real tie to attach to. Emission (:2252-2291): a merged length under $80 is written as len (only if it differs from the previous note's, or a q is pending), then the pending q byte, then the note. A merged length of $80 or more is split: $60, [q], note, then as many $C6 ties as whole $60s remain, then the remainder as len $C6. The driver's duration byte is seven bits, so $60 is chosen as the largest clean half-note.

2.2 q — what the readme says versus what the bytes do

The readme: “The first digit specifies how long of a delay there is between each note … The second digit controls the volume” (syntax_reference.html:107). The driver (main.asm:2366-2380): the high nybble is and #$07 and indexes NoteDurations — a gate time in 256ths of the note, so q7x sounds for the whole note and q8x–qFx alias q0x–q7x; the low nybble indexes VelocityValues, a non-linear 16-entry table of which there are two, chosen by !SecondVTable. The compiler accepts $01–$7F and never sees the aliasing. Tables in §5.

2.3 @, the percussion set and the built-in tables

@0–@18 are the driver's built-in instruments; @21– @29 are percussion; @30 and up are the song's #instruments in order. @19 and @20 are holes that emit nothing. Two constant tables drive the compiler's view (Music.cpp:57-61): 

tmpTrans[19]    = { 0, 0, 5, 0, 0, 0, 0, 0, 0, -5, 6, 0, -5, 0, 0, 8, 0, 0, 0 }   // seeds transposeMap[@0..@18]
instrToSample[30] = { 00 01 02 03 04 07 08 09 05 0A 0B 01 10 0C 0D 12 0C 11 01   // @0..@18 → SRCN
                      00 00                                                         // @19, @20
                      0F 06 06 0E 0E 0B 0B 0B 0E }                                  // @21..@29

A note under @21–@29 becomes $D0 + (N−21) (:2178-2180), and on every channel but 6 and 7 (the SFX channels) the instrument is then forgotten (instrument = 0xFF, :2182-2183) so the drum pitch is not re-forced on later notes; #am4/#amm forget it on every channel. The driver side of a percussion byte is in §5.

2.4 Loops

  • [ ] switches writing to “channel 8”, a shared body area; ]N appends $00, switches back and emits $E9 lo hi N (Music.cpp:1233-1253, 1300-1312). Every $E9 address is patched in pointersFirstPass via loopLocations.
  • Nesting matrix: [ in [ — error; [[ in [[ — error; [ in [[ and [[ in [ — allowed. A label loop may not define a subloop. Remote-code bodies may not repeat.
  • Label (L) is stored at loopPointers[L+1]; an undefined label is 0xFFFF and calling it is an error (:1178).
  • [[ ]]N emits N−1 (:1288) and the driver's $E6 plays arg+1 passes; $E6 written by hand is checked the same way (:1985-2006), with $E6 $00 opening and $E6 n closing.

2.5 The “fade” forms below #amk 4

v, w and t look for a comma only when targetAMKVersion >= 3 (Music.cpp:616, 651, 769). Under any other target, v24,200 emits $E7 $18 and returns; the main loop then meets ,, 2, 0, 0 one at a time and prints “Unexpected character” for each — through std::cout, so errorCount is untouched and the song compiles with a volume of 24 and no fade. The readme lists the fade syntax under #amk 3/#amk 4 (syntax_reference.html:430-438).

3. # directives

A # followed by a digit is a channel; followed by a letter it goes to parseSpecialDirective (Music.cpp:551-578, 2413-2509). Some directives never get that far because the preprocessor has already eaten them (§1.1). The two layers have different case rules and different tolerance for trailing text — see §1.2 “Case” — and the parser layer has no final else, which is §3.3.

3.3 Unknown #words are read as music

parseSpecialDirective is an if / else if chain with no final else (Music.cpp:2508). An unmatched #word returns with pos on its first letter and the main loop parses the letters as MML — silently, since none of this goes through an error path unless a letter happens to be a command that then fails. Consequences worth knowing:

  • #error → note e, rests, then “Error parsing octave” (§3.1).
  • #nspcvtable and #smwvtable as bare directives (the readme names #nspcvtable at syntax_reference.html:425) → n with a non-hex argument → “Invlid value for the n command” (sic); s is then an unexpected character.
  • #nospc → the same n error. It does not exist in 1.0.11.
  • #amk4 (no space) → notes a, then m, k, 4 as unexpected characters.
  • #if reaching this layer (it cannot, unless written #IF) → nothing matches → i unexpected, then the note f.

4.2 Rules that apply to every hex command

The first byte — Music.cpp:1683-1779, in evaluation order

  1. i > $F2 under #am4: one-shot warning “not native to AddMusic405. Did you mean: #amm”. i > $FA under #amm: one-shot warning “not native to AddMusicM. Did you mean: #amk 1” (:1687-1694). Neither changes the bytes.
  2. i < $DA: under #am4/#amm (targetAMKVersion == 0) a one-shot warning per class — “will act as a note” (≥ $80), “as a duration or a quantization and velocity byte” ($01–$7F), “as a phrase end marker” ($00) — and the byte is appended raw. Under any #amk: “Unknown hex command.” (:1695-1719).
  3. i > $FE, i.e. $FF: “Unknown hex command.” for every target (:1720-1723).
  4. $ED under #am4 → parseHFDHex (:1724-1728).
  5. $FB: the sub-byte is read at once; ≥ $80 leaves 2 more bytes, otherwise sub + 1 more (:1729-1746). The range check on the sub-byte tests the wrong variable (if (j == -1 || i > 0xFF), :1736), so a three-digit sub-byte is not caught here.
  6. $E5 under #am4: nothing appended yet; decided on the next byte (:1747-1752).
  7. $FC under #amk 1: the two-byte remote-gain form; nothing appended yet (:1753-1767).
  8. Otherwise hexLeft = hexLengths[i − $DA] − 1; $E3 also switches off length guessing (:1768-1773).
  9. $FC under #amk 2 (1 < version < 4): one-shot warning that it is five bytes now and errors on 1.0.8 and lower (:1774-1778).

Argument bytes — Music.cpp:1780-2090

hexLeft is decremented first, so the tests below see the count of bytes still to come after this one. Each card quotes the tests that concern it; the common tail is: i == -1 → “Error parsing hex command.”; outside 0–255 → “Illegal value for hex command.”; then append(i) (:2094-2106). The driver's read-ahead — ShouldSkipKeyOff, main.asm:2949-3186

Before keying a note off, the driver scans forward from the track pointer to see whether the next event is a tie. It skips positive bytes, stops on $C6 (keep sounding) or on anything below $DA (key off), and steps over commands using CommandLengthTable (:3032-3039) with two special cases: $FB (:2988-2998, +4 if the count byte is negative, else count+3) and $FA (:3000-3015, and for $FA $FE it reads on while bytes have bit 7 set). It follows $E6/$E9 only when hot-patch bit 2 is on (:3022-3031). This scan is where a wrong table length — $E5 — and a zero one — $FF — do their damage.

$FF — nothing

Compiler
“Unknown hex command.” for every target (Music.cpp:1720-1723); hexLengths[] stops at $FE.
Driver
CommandLengthTable has an entry, 0; CommandDispatchTable does not. The dispatcher's 8-bit index wraps to $13B6/$13B7 — the first two bytes of the length table, 02 02 — so it rets to $0202, channel 1's duration byte in RAM, having fetched one argument because dec a on 0 is not zero. The read-ahead is worse: it adds a length of 0 to its pointer and loops forever on the same byte (main.asm:3032-3039). Only reachable with -h or a corrupted song.
Targets
error everywhere.

6. Hot patches — $FA $7F and $FA $FE

Added in 1.0.9 so that old songs keep their old playback quirks while new songs get the fixes. Both are self-modifying code: each bit selects one of two bytes to write over an opcode or operand in the driver (“storage set” format, Commands.asm:830-834). PlaySong resets every bit to 0 at the start of each song (main.asm:2103-2106), and the compiler's prologue then applies the preset for the target (§1.3). #option amk109hotpatch is $FA $7F $01.

Appendix B — discrepancies

B.1 Readme versus source

  • $DB: “Must be between $00 and $13” — PanValues has 21 entries and $14 is hard left (hex_command_reference.html:235; main.asm:3486-3488).
  • q: “how long of a delay there is between each note” / “controls the volume” — a gate-time index masked to 3 bits, and a velocity-table index (syntax_reference.html:107; main.asm:2366-2380). §2.2.
  • “all ‘special’ commands are case insensitive” — the preprocessor's directives and the #spc keys are case-sensitive (syntax_reference.html:444; globals.cpp:925, Music.cpp:3471). §1.2.
  • $FA $06 is not in the readme at all; #option smwvtable/nspcvtable and the prologue emit it (Music.cpp:2348-2363, 2994-2996).
  • $F7 appears only as AddmusicM history, “not compiled by default” — yet the compiler accepts it everywhere and the driver crashes on it (hex_command_reference.html:1134-1149).
  • $FC types 5 and 6 are “Reserved. Do not use.” — and are exactly what the compiler emits for #amk 1 remote gain and $FA $05 (syntax_reference.html:192-193; Music.cpp:1906-1910, 1940-1944). Types 7, 8 and −1 are documented only in the syntax reference, not in the hex reference.
  • $FA $05: documented as replaced in #amk 2 — under #am4 it is neither rewritten nor refused and reaches a null slot (Music.cpp:1841, 1925).
  • #error is documented and does not exist (syntax_reference.html:403). §3.1.
  • #nspcvtable is named as a directive (syntax_reference.html:425); only the #option form exists. §3.3.
  • #option is presented as an #amk 2 addition; it is refused only for #amk 1 and works under #am4/#amm (Music.cpp:2335).
  • o: “Valid values are 1 to 6” — the code accepts 0 (Music.cpp:861).
  • The < and > rows have their examples swapped (syntax_reference.html:57-67).
  • DSP register table: EDL is listed at $7C; the driver writes it at $7D (hex_command_reference.html:1733; Commands.asm:528).
  • $FA $7F: “$80-$FF - User-defined Preset ID” — the hook is commented out (Commands.asm:686).
  • The #amm preset note in the changelog names the $F3 fix; preset 5's bit is the $DD one (§6.2).
  • Undocumented but real: tuning[N]=, |, bare #tempoimmunity, ?1/?2, @@N, #amk=1.

B.2 Driver versus compiler

  • $E5: CommandLengthTable says 3, hexLengths[] says 4; the handler consumes 3 arguments. The driver's table is wrong (main.bin @ $13C1; Commands.asm:349-353; Music.cpp:64).
  • $C8–$CF are rests to the driver; the compiler only ever writes $C7 (main.asm:359-363).
  • q8x–qFx alias q0x–q7x in the driver; the compiler accepts $01–$7F without comment (main.asm:2368; Music.cpp:682).
  • $FA $06: any non-zero value selects the N-SPC table; the compiler only writes 0 and 1 (main.asm:2374).
  • $F4 and $FA sub-bytes: unbounded in the driver, unchecked in the compiler.
  • $DD: a null dispatch slot; the compiler accepts it anywhere.
  • $FB and $FF: placeholder lengths differ (3 vs 2; 0 vs absent) — harmless for $FB, fatal for $FF.

B.3 Solar Soundtrack versus source

Line numbers are as of this document's writing; they will drift.

  • packages/mml-compiler/src/parser.ts parsePath — the one deliberate divergence in the port. #path is read and validated and then applied to nothing: no basepath exists, and the three join sites (Music.cpp:958, :2594, :2717) resolve the quoted name as written. The editor's sample library is one flat list of filenames matched verbatim, with no directory to resolve a prefix against, so the faithful behaviour makes every sample under a #path fail with AMK0058 naming a folder that cannot exist. The syntax is still the source's — the quoted string is required and consumed, so AMK0052, AMK0064 and AMK0068 all still reach it — and AMK0504 reports the no-op at info, once per occurrence. packages/mml-compiler/AUDIT.md carries the reasoning.
  • packages/mml-tokens/src/commands/hex-params.ts REMOTE_TYPES now names 4 “run once, right now”, 5 and 6 as the reserved pair the compiler emits, and carries 7, 8 and $FF (−1); a type in $09–$FE is described as stored and never run. Agrees with the $FC card.
  • packages/mml-tokens/src/tokens.ts VCMD_NAMES still names $F7 “write byte”, which is what it was meant to be; the palette entry in web/src/app/editor/command-palette/catalog.ts carries a caveat saying the slot is $0000 and the SPC dies. A $DD away from a note and #am4's silent $E4 offset are said the same way — availability.ts answers to the compiler's diagnostics, and none of the three produces one.
  • packages/core/src/hardcoded-tables.ts HEX_LENGTHS (:27-29) equals hexLengths[] byte for byte — including the $E5 value the driver's own table disagrees with. That is the correct choice for a compiler that mirrors AddmusicK; packages/spc/src/song-walk.ts vcmdLength inherits the same value when walking compiled data, and so would step over $E5 the way the compiler thinks, not the way the driver's read-ahead does.
  • packages/mml-tokens/src/commands/availability.ts gates fades and (!!N) at #amk 3, remote code at #amk 2 and l=N at #amk 4 — the same thresholds as the source, with 3 unreachable — and warns on h under #am4 (AMK0205).   • packages/mml-tokens/src/tokens.ts gather and hex-params.ts's $FA $06 row both read the version the way Music.cpp does: a two-argument t/v/w is a fade only at #amk 3 and above (§2.5), and the #option spellings are named for every target but #amk 1, which is the only one that refuses the directive (§3.2).
  • packages/mml-compiler/src/parser.ts (:3203-3217) documents two deliberate departures from Music.cpp:1981's *5 stride in the #am4 $DA remap; the $DA card above records the source bug they depart from.
  • Open: under #am4, an $E5 with a high first byte reaches no piano roll bar. The parser emits $F3 for it (parseHexCommand, the $E5 card), and the address that byte lands at is not mapped back to the $E5 written in the source, so commandMap has nothing for the walk to name. The plain tremolo form and every other note-state command do reach it. The inspector, which reads the source command rather than the walk, is unaffected.
  • web/src/app/output/command-inspector/quantization-command/quantization-command.ts (:20-37) and …/pan-command/pan-command.ts (:28-40) already carry the q and $DB corrections above.
