# Harnesses

Thirteen byte-level checks, each a standalone esbuild-bundled Node script with its own npm script.
There are no `.spec.ts` files anywhere in the repository — `npm run test` is Angular scaffolding and
currently runs nothing. These are the real suite.

Run one by name (`npm run selftest`). They take no filter flags, so narrowing a run means editing
the harness. `npm run check` runs all thirteen, grouped:

| Group               | Harnesses                                         |
| ------------------- | ------------------------------------------------- |
| `check:compiler`    | `selftest`                                        |
| `check:tokens`      | `tokentest`, `edittest`, `palettetest`            |
| `check:spc`         | `adsrtest`, `instrtest`, `brrtest`, `firtest`     |
| `check:integration` | `spctest`, `audiotest`, `worklettest`, `walktest` |
| `check:app`         | `charttest`                                       |

Eight of the thirteen straddle two packages, which is why they all live here rather than one per
package — and why they share `harness.ts` rather than each carrying a copy. They did carry copies
once, and the copies had already drifted: `worklettest.ts` said "same shim as spctest" above a shim
that had lost both of the behaviours `spctest.ts` documents as load-bearing.

| `selftest`    | Compiler output, byte for byte. Also that diagnostic spans land on the offending character, not merely near it.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                            |

Also pins every address in `assets/driver/manifest.json` against the bytes of the shipped `main.bin`: nothing derives those at runtime any more, so this is the only thing standing between a rebuilt driver and an `.spc` that assembles cleanly against the wrong addresses.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                        |
| `audiotest`   | MML → SPC → actual PCM through the real wasm host. **This is what proves the whole pipeline**: a wrong compiler, layout, sample directory or CPUIO handshake produces silence.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                             |
| `worklettest` | Evaluates the _built_ `spc-worklet.js` inside a `vm` context holding only what an AudioWorkletGlobalScope really exposes — no `fetch`, no `setTimeout`, no `TextDecoder`. Node has all of those globally, so this catches worklet-only breakage that `audiotest` structurally cannot.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                      |
| `charttest`   | Stacked-bar geometry for the ARAM bar, the shared plot space, `clamp`, and the piano roll's lanes, window arithmetic and percussion set. Five roll claims live here, none of them visible in a screenshot: that the playhead's clock absorbs a steady lag instead of re-correcting it on every anchor, which is the difference between a smooth scroll and one that jerks ten times a second; that "all octaves" widens the pitch range without conjuring a drum lane the song never plays; that sweeping a playhead rebuilds the mark window about twice per whole note rather than once per frame, which is what keeps a scroll off the DOM; that a drum the porter takes off the percussion lanes falls back to the note the driver's own table gives it rather than vanishing, having neither a lane nor a key; and that an empty stored percussion set is kept rather than read as "no opinion", which would make turning everything off undo itself on reload.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                       |
| `walktest`    | The song-data walker, `@amk/spc/song-walk`, which is the only thing the piano roll draws from — and a walker that mis-frames one command draws a plausible roll that is quietly wrong, with no visual tell. Three assertions carry it. **The two packages are pinned together**: `@amk/spc` may not reach `@amk/tokens`, so each states how long a VCMD is, one about emitted bytes and one about source text, and this asserts they agree at every `$DA`-`$FE`, every `$FB` count and every `$FA $FE` chain length — the only thing that makes the restatement safe. **`$FB`'s arguments are not notes**: an arpeggio's operands sit in the `$80` range without being notes, so pricing `$FB` at a fixed length invents a chord out of nowhere and still yields a timeline that reads as reasonable. **The emulator is the oracle**: tick totals matching `stats` only prove the walk agrees with AddmusicK's own prediction and both could be wrong together, so the real driver is run and the note the walk predicts is compared against the one each voice's track pointer is actually on. It also pins that `@29 o2a1b2c3` is one drum then two pitched notes on `#0` but three drums on `#6`, which is the channel-dependent behaviour that makes walking bytes worth doing at all.                                                                                                                                                                                                                                                                                                                 |
| `brrtest`     | BRR container handling and the decoder. Cross-checks `BANK_SLOT_COUNT` against `@amk/spc`'s own `SAMPLE_BANK_SLOTS`.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                       |
| `tokentest`   | The MML scanner. Its load-bearing assertion is **restartability**: stepping line by line with the state carried across must equal scanning the whole document. CodeMirror restarts the scanner at arbitrary lines, so a state machine that secretly depended on having seen the top of the file would pass a whole-document test and mis-colour text much later. It also holds the inspector's two arithmetic claims about a fade, both of which read as plausible while being wrong: a tempo fade's seconds are checked against a closed form derived independently of the per-tick walk that produces them, because `$E3` is the one command whose duration cannot be priced at the tempo in force; and every fade command is checked to report a duration of 0 as dropped rather than instant, which is what the driver does with it.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                   |
| `firtest`     | The echo FIR maths, anchored on the two filters in the SNES manual that AddmusicK ships as `EchoFilter0`/`EchoFilter1`, and on bsnes's own DSP behaviour. Also the echo-hazard diagnostics built on it.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                    |
| `instrtest`   | The driver's instrument and percussion tables. Its load-bearing assertion is that `instruments.ts` finds them in `main.bin` **uniquely** — the tables carry no citable address, so they are located by matching the SRCN column against `INSTRUMENT_TO_SAMPLE`, and a second candidate would make that a guess. It also pins the one index where the driver and `Music.cpp`'s `instrToSample` disagree: 19, which is the whole `@19` story.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                |
| `adsrtest`    | The envelope maths. `CLOCKS` is checked against the _published SNES noise ladder_, because the DSP uses the same table for noise and every other function there is defined in terms of it; nothing else could catch a transposed digit. It also asserts that the two magic tables in AddmusicK's readme calculator are exactly the step counts of bsnes's envelope stepping.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                               |
| `palettetest` | The command palette's catalogue, and it is the one harness whose oracle is the compiler rather than a table of expected bytes. Three assertions carry it. **Values, never arity**: an entry lists argument values and `expectedArgs` decides how many there are, so this asserts the two meet exactly under every dialect — a snippet one byte short does not look wrong, it swallows whatever follows as its own argument and still compiles. **Availability is a prediction**: `formAvailability` ports conditions `parser.ts` tests on text that exists to text that does not, so every entry is compiled in a minimal song at `#amk 1/2/4`, `#am4` and `#amm` and checked against what actually comes back. `blocked` asserts the song is not clean rather than that it errors, because the quieter failure is the worse one — `t18,144` below `#amk 3` builds and silently means `t18`. **Supersession is proven, not claimed**: the palette offers `t144` and not `$E2`, so `SUPERSEDED` compiles both spellings and compares the output byte for byte, and `ENTRIES` plus that table has to cover all of `$DA`-`$FE` — a VCMD added to `tokens.ts` fails here until it has a button or a letter form that writes it. Three rows can only be checked differentially, and why is worth reading: `$E9` and `$FC` carry an address the compiler works out for itself, and `[[ ]]` re-emits the standing note length inside the loop where a hand-written `$E6 $00` does not. It also pins that every glyph the icon component names has a `@case` in its template, which nothing in TypeScript can see. |
| `edittest`    | The splices the command inspector writes back into the source. Two load-bearing assertions, both comparing whole strings rather than numbers because numbers cannot see either failure. **Gap preservation**: a tab, a column of aligned bytes or a mid-run `; comment` survives an edit to the byte beside it. **The macro interlock, per part**: `"ech=$EF"` used as `ech $80 $10 $10` has a macro for its command byte and literal text for every argument, so the arguments are writable and the byte is not.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                          |

## `harness.ts`

`check`, `summarise`, `failureCount`, `SPC_ASSETS` and `stubFetch`. Use them rather than writing
another copy.

`stubFetch` reproduces two dev-server behaviours deliberately, and between them they produced the
"invalid BRR length 2205" bug:

1. paths are decoded with `decodeURI`, which leaves `%40` untouched, so an over-encoded `@` never
   resolves to a real file;
2. an unresolved path is answered 200 with index.html, not 404 — so code that trusts `response.ok`
   gets HTML where it expected bytes.

A harness that threw on a missing file instead would pass while the browser failed.

## What none of them cover

**Angular templates.** Neither these nor `npm run typecheck` run the template compiler, so a bad
binding (`viewBox=` instead of `[attr.viewBox]=`) passes `npm run check` and fails only at
`npm run build` / `npm start`. Run one of those before believing a UI change.

## Establishing fidelity

`Compare-Spc.ps1` and `Compare-SongBin.ps1` diff output against a real AddmusicK build, region-aware
so ID666 noise does not drown the real differences. Those are what establish fidelity; the harnesses
only catch gross breakage.

`Compare-SongBin.ps1` is the sharper of the two: AddmusicK writes `asm/SNES/bin/musicXX.bin` for
every song it compiles, and past its 12-byte RATS header that file is exactly the blob this editor's
`.bin` export produces. Same song, same load address, so every difference is a real compiler
difference rather than a layout artefact. Run it with one argument to read the header and see which
address to compile at.
