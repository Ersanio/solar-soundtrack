# Code map

Every source file under `packages/*/src`, `web/src` and `scripts`, with the first sentence of its
doc comment. Generated by `npm run codemap`; `npm run check` fails when it is stale. Do not edit by
hand — change the comment and regenerate.

## packages/core/src

- `hardcoded-tables.ts` — Constant tables lifted from AddmusicK's `Music.cpp` and `main.asm`.
- `hex.ts` — Uppercase hex with no prefix: bare, padded to a byte (`hex2`) or to a word (`hex4`).
- `mml-text.ts` — How a parse-time value is spelled as MML.
- `types.ts` — What goes into the compiler and what comes out of it.

## packages/core/src/messages

- `amk.ts` — The message of every `AMK` diagnostic: conditions AddmusicK itself reports.
- `sst.ts` — The message of every `SST` diagnostic: findings this tool makes that AddmusicK does not.

## packages/mml-compiler/src

- `index.ts` — The compiler's entry point: `compiler.compile` parses and links one request and gathers its stats and diagnostics.
- `link.ts` — Turns the parser's per-channel byte vectors into the final relocated blob.
- `parser.ts` — AddmusicK MML parser.
- `preprocess.ts` — Port of `preprocess()` (globals.cpp:735), which runs before the MML scanner.

## packages/mml-tokens/src

- `command-hazards.ts` — The command hazards: commands that compile clean and misbehave — `$F7`'s dead slot, an unreachable `$DD`, `#am4`'s `$E4`.
- `dialect.ts` — What was in force at a point in the song:
- `echo-hazards.ts` — The echo hazards: every runaway echo in the document, one diagnostic per command that causes one.
- `edits.ts` — Rewriting a command in the source it was scanned from — the inverse of `gather`.
- `fir-override.ts` — The `$F1`/`$F5` override, looked at from either end.
- `index.ts` — The scanner.
- `tokens.ts` — A resumable scanner over MML source.

## packages/mml-tokens/src/commands

- `availability.ts` — Whether the dialect a song declares will take a given command, and what it says about it if not.
- `describe.ts` — The command's parameters, bound to what it actually says.
- `hex-params.ts` — `HEX_PARAMS`: every hex command's arguments, named as AddmusicK's hex command reference names them.
- `in-force.ts` — Which commands act on a note, and which of them the source alone can answer.
- `instruments.ts` — Which instrument an `@`, an `@@` or a raw `$DA` selects, and which number a given spelling has to carry to select a different one.
- `letter-params.ts` — `LETTER_PARAMS`: the arguments of every letter command (`t`, `v`, `l`, `o`, `@`, `p` and the rest), as the inspector edits them.
- `loops.ts` — Where a song's loop brackets are, what each construct repeats and names, and which label numbers it has already used.
- `param.ts` — The vocabulary the inspector describes an argument in: codecs, roles, controls, and builders for a command's parameters.
- `remote.ts` — Remote code calls and resets — `(!n, type[, wait])` and `(!!n)` — and the body a call runs.
- `units.ts` — Turning driver bytes into the units a musician thinks in.

- `driver-state.ts` — Our SPC driver's I/O through the emulator's ARAM.

- `fir.ts` — The DSP's echo FIR filter: what eight signed bytes actually do to a sound.

- `layout.ts` — ARAM layout and budgeting.
- `note-audition.ts` — Playing one note as it would sound at a point in the song, or one stretch of the song as it stands.
- `player.ts` — SPC700 playback.
- `protocol.ts` — The message contract between `player.ts` on the page and `worklet.ts` on the audio thread.

## web/src/app/state

- `audition.ts` — Playing one sample, one note of the song, or one stretch of it, on its own AudioContext.
- `clock-measurer.ts` — Measures how fast the song really runs on the emulator, and raises `SST0503` when the driver falls behind.
- `clock.worker.ts` — Runs {@link measureClock} off the page.
- `command-timeline.ts` — Every command that takes effect, and the tick it runs at.
- `commands-in-force.ts` — The commands acting on a walked note, exactly — a lookup rather than a map.
- `commit-audition.ts` — Replays the selected note when a command inspector panel commits a value.
- `driver-store.ts` — The N-SPC driver and the ARAM layout that goes with it.
- `editor-requests.ts` — What a panel asks the editor to do, and what the view and the roll report back.
- `editor-store.ts` — The document and everything compiled from it: the debounced compile, diagnostics, stats, the budget, the walk, the SPC.
- `measure-clock.ts` — The song's clock as the driver actually keeps it, by running the emulator.
- `mixer.ts` — Which channels are heard, how loudly, and which the porter has taken out.
- `note-transpose.ts` — Which byte to play for a pitch the porter has not written yet.
- `note.worker.ts` — Runs {@link auditionNote} and {@link auditionRegion} off the page.
- `playback.ts` — The transport: plays the compiled song through the worklet player and holds the one playhead, in driver ticks.
- `repeat-carry.ts` — `SST0510`-`SST0512` — a looping song whose repeat starts its loop under a different tempo, channel setting or song setting from its first pass.
- `sample-song.ts` — The song a fresh editor opens on.
- `sample-store.ts` — The sample library: the bundled `.brr` files plus whatever the user has uploaded over or alongside them.
- `song-clock.ts` — Ticks to seconds, for a song the compiler could not put a clock on.
- `spc-core.ts` — One emulator per worker, brought up on demand.
- `stop-all.ts` — Stops whatever is sounding: the song, and a note or selection being previewed.
- `theme-store.ts` — What the app is painted in, and the porter's changes to it, written onto `<html>` as custom properties.
- `transport-view.ts` — The transport's readings of the mixer and the walk: silenced channels and why, sounding spans, estimated seconds.
