# Text and i18n

Read before adding or changing any text a porter reads: a template, a `$localize` message, a
diagnostic, a command name or parameter description, or `web/src/locale/messages.json`.

Every user-facing string goes through Angular's i18n (`@angular/localize`) with a custom ID, so the
whole set is listed, grouped, in one catalog. Only English ships: nothing is translated at build
time, and `$localize` runs in the page, returning the source text. A second locale is not set up.

## Where text lives, and how to change it

The English is written where it is used. To change a string, find it in
`web/src/locale/messages.json` by ID, `grep` the ID, edit it at the source, and run `npm run i18n`.
The catalog is generated — nothing reads it at runtime — and `npm run check` fails when it is stale.

- **Templates** keep their text inline beside an ID: `i18n="@@id"` on the smallest element holding
  a whole sentence (inline `<code>` and `<strong>` stay inside the message), `<ng-container i18n>`
  for text beside an icon, and `i18n-title`, `i18n-label`, `i18n-heading`, `i18n-note` or
  `i18n-legend` on a static attribute. Interpolation in an attribute works
  (`title="Mute channel {{ n }}"`).
- **Bound text** cannot take an `i18n` attribute. A ternary between two strings becomes a
  `protected readonly text = { … }` of `$localize` messages on the component, declared after its
  `inject()` fields; a ternary inside a sentence becomes `@if` branches or an ICU `select`.
- **TypeScript** uses `` $localize`:@@id:text` `` where the string is used, every placeholder named
  (`${count}:count:`) so the catalog reads `{$count}`. Module-level messages are fine: the
  polyfill loads before the app, and every harness imports `@angular/localize/init` first.
- **Plurals** are an ICU `plural` in a template, and two messages (`.one`, `.other`) chosen in code
  in TypeScript, since `$localize` takes no ICU.
- **Whole sentences.** A message is never glued from fragments round a condition; each branch gets
  a message of its own, even where most of the words repeat.
- **Text is never a key.** Where code compared a string a porter reads, it compares a stable key:
  `FIR_PRESETS` match on `id`, and `loop-wrap.ts` tells a note by its `noteLength`.

Interpolations in templates keep Angular's default placeholder names (`{$INTERPOLATION}`). Naming
them takes a `// i18n(ph="…")` comment, and Prettier then splits every interpolation over three
lines.

## IDs

`group.segment[.segment…]`: lowercase letters and digits, hyphens inside a segment. The group says
**where the porter reads the text, not which file holds it** — the same rule as a diagnostic's
prefix. Attribute texts end in their role (`.title`, `.label`, `.heading`, `.note`); TypeScript
plurals end in `.one` / `.other`.

| Group                          | Text                                                                                  |
| ------------------------------ | ------------------------------------------------------------------------------------- |
| `amk`, `sst`                   | diagnostics, by code and variant: `amk.0058`, `amk.0096.rate`, `sst.0502.other`       |
| `command`                      | the shared command vocabulary: names, note lengths, units, intervals                  |
| `inspector`                    | the command inspector and its panels, the parameter table, FIR presets, GAIN modes    |
| `loops`                        | the loop inspector                                                                    |
| `palette`                      | the command palette: categories, blurbs, caveats, refusals, availability              |
| `roll`                         | the piano roll: toolbar, refusals, tooltip, drag readouts, percussion                 |
| `source`, `editor`             | the source view and its hover; the editor pane's tabs                                 |
| `samples`                      | the sample browser                                                                    |
| `transport`, `mixer`, `topbar` | the transport, the channel mixer, the top bar and its history buttons                 |
| `output`                       | the output pane: build, problems list, hex dump, stats, ARAM                          |
| `status`                       | the status bar and the status line                                                    |
| `theme`, `changelog`, `update` | the theme picker, the changelog popup's chrome, the update banner                     |
| `error`                        | failures shown to the porter: driver, export, BRR and sample bank validation, storage |
| `common`                       | shared components                                                                     |

`scripts/i18n-catalog.mjs` holds the group list and rejects any other, and any ID not in this
form — a `$localize` without `@@id` gets a numeric one, so that is where a missing ID surfaces. One
ID may serve several places when the text is identical; extraction fails on one ID with two texts.

## Diagnostics

The text of every diagnostic is in one of two catalogs in `@amk/core`, since `SST` codes are raised
from three packages and the app: `messages/amk.ts` for `AMK`, `messages/sst.ts` for `SST`. Each
entry is keyed by code, or code and variant, is a function so nothing runs `$localize` at import,
and cites the AddmusicK line it ports. The call site states the code and calls the entry —
`this.error("AMK0058", AMK["0058"](name))` — and the two must agree. A new diagnostic adds its entry
to the catalog of its prefix.

## Packages, workers and the worklet

The packages use `$localize` as a host-provided global and import nothing from Angular, so the
package boundary in `eslint.config.js` stands; each package's tsconfig names its types. The page
loads it as a polyfill, the harnesses by import.

A worker and the AudioWorklet have no `$localize`. Their import graph — `worklet.ts`,
`protocol.ts`, `driver-state.ts`, `wasm-host.ts` and `note-audition.ts` in `@amk/spc`, and
`spc-core.ts` and `measure-clock.ts` in the app — holds no message, and its errors stay English.

## Not marked

The changelog's entries (its popup is), `index.html` and the web manifest, which Angular's i18n does
not read, `README.html` and `COMMANDS.html`, MML spellings, dialect tags such as `#amk 4`, colours,
and number formatting. `listOf`, `capitalise` and lowercasing a label for a sentence are English
grammar, and would need rework before a second locale.

## Decisions already made

- **Diagnostic text at its call site** — each `error()` carried its own English, so one code's
  texts were spread through `parser.ts` and the `SST` ones through three packages. They are two
  catalogs in `@amk/core` now: one place per prefix to read and edit them, a repeated text written
  once, and the AddmusicK line each ports cited beside it.
- **Strings a porter reads used as keys** — `builtInTaps` found a FIR preset by its name, and the
  loop wrap told a note by `command.name === 'note'`. Translating either would have changed what
  the code does; both match on a stable key now.
